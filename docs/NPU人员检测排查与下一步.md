## 已完成的优化

此前 NPU 的前向推理平均约 **21.17 毫秒**，但预处理、前向、后处理的图像总耗时平均约 **246.03 毫秒**；DAMO CPU 对照约 **261.33 毫秒**，所以原报告只有 `1.062` 倍加速。

旧预处理每张图都会启动 `ffprobe` 和 `ffmpeg`。已改为进程内 Pillow 解码加 NumPy 双线性缩放，保留该官方模型对应的 BGR、拉伸到 640×640、除以 255。默认通道和几何方式没有按通用 YOLO 教程盲目切换。

还使用本机官方包的 `test_data/1.jpeg` 和 `datasets/input0.bin` 检查了像素一致性。平均绝对像素差，按 0–255 像素单位计：旧 BGR 预处理为 **1.49**，新 BGR 为 **0.12**，新结果交换成 RGB 后为 **25.79**。这支持继续使用 BGR，并说明新缩放更接近这个官方样本；它不等于检测准确率提高，新输入下的检出效果仍待真实 NPU 复测。

## 你现在执行这一条诊断命令

在板卡普通桌面终端中执行：

```bash
cd /home/orangepi/emergency-agent
./diagnose-person-npu.sh
```

默认对六张图片比较四种输入：旧版 FFmpeg BGR 拉伸、新版 BGR 拉伸、RGB 拉伸、RGB letterbox。BGR 拉伸是当前默认；其余方式只用于诊断。模型只加载一次，每种图片和输入组合预热一次、测量三次。

最后会打印 `report.html` 的绝对路径，形如：

```text
/home/orangepi/emergency-agent/data/npu-diagnostics/20261124-xxxxxx-xxxxxx/report.html
```

用浏览器打开这个文件。同目录还包括：

- `report.json`：全部输入方式、人数、逐次稳定性、预处理和前向耗时。
- `样例名-输入方式.jpg`：默认置信度 0.5、NMS IoU 0.45 下的实际检测框。
- `样例名-输入方式.npz`：对应原始 NPU 输出，供后续离线检查。
- `样例名-输入方式.json`：候选框、逐次人数、不同置信度和 NMS 的人数表；中途失败时保留已完成样例。

这个命令只诊断，完成后保持当前模型配置。`diagnosis_complete_manual_review_required` 表示采集完成，需要看框复核，不能当作启用成功。

## 怎么根据报告继续

优先看六人图，按以下顺序定位：

| 观察到的结果 | 下一步 |
| --- | --- |
| 新 BGR 输入下漏检减少 | 对照真实人员位置检查框，再用独立样例验证这项输入修正 |
| 降低置信度后出现原先漏掉的人 | 检查低分框是否对应真人，在独立负样例上同时评估新增误报 |
| 放宽 NMS 后相邻人员被分开 | 检查新增框是否对应不同的人，并检查重复框；再评估其他场景 |
| 多种阈值下仍没有独立人员框 | 检查原始候选输出，评估遮挡和小目标能力，考虑更合适的模型或训练 |
| 报错而非正常给出检测框 | 先查看 `report.json` 中的 `error`；输出尺寸、无效数值和反量化错误不会被伪装成“零人” |

不能仅凭调出“人数等于六”就切换。后续恢复启用验收前，需要补全或替换不完整参考样例、更新验收参考集，并用独立于调参的图片或视频检查漏报、误报和稳定性。之后才使用 `./test-person-npu.sh --activate` 做样例验收与配置切换。目前直接反复运行该入口仍会被不完整参考阻止。

如果这版通用 COCO YOLO 始终不能满足人员场景，可以继续使用当前 DAMO CPU 演示。另有两份 DAMO `.cix` 编译结果在 `data/cix-compiled-20261124.tar.gz`（解压目录 `data/cix-compiled-20261124/`）；压缩包哈希校验通过、两份编译日志均显示 `build success`。它们尚未做 NOE 运行或精度验收，当前项目也没有匹配的 DAMO CIX 适配器，不能直接替换 CPU 权重。具体输入输出和接入要求见 [CIX迁移说明](CIX迁移说明.md)。
