# 应急先行：5 分钟 Demo 演讲稿

## 演示逻辑

按“现场为什么需要它 → 系统如何主动发现 → Agent 如何按需调用工具 → 结论如何核验 → 还缺什么”展开。先展示项目最有辨识度的持续巡查，再展示一张图上的多工具 Agent，最后用限制和下一步收尾。不要按菜单顺序介绍功能。

## 演示前准备

- 在板卡上启动项目网页或桌面程序，确认能打开工作台。
- 查看“设备与模型”状态条。按屏幕实际显示说明后端；当前项目人员检测、烟火检测和 Qwen 都走 CPU 配置。前一次 YOLOv8s NPU 对照未通过验收，所以不要说本次网页由 NPU 推理。
- 在持续监测的视频列表选“照片演示 01 · 基础轮巡 · 72秒”，间隔设为 2 秒，关闭循环，人员检测保持开启。素材约在播放 8 秒进入人员画面、16 秒进入烟火画面；烟火事件出现后就点“停止”，不需要等完整 72 秒。素材由静态照片拼接，不是真实连续视频。页面提示音只在浏览器启用后播放，不代表开发板蜂鸣器或远程通知。
- 准备烟火样例：**samples/fire-smoke/ESE_fire_10.jpg**。现场分析的问题填写：“检查图片中有没有烟雾或明火，并给出有依据的避险建议。”
- 如果现场推理过慢，准备打开历史记录中的同一张样例报告作为备用；明确说这是此前的一次运行记录，不冒充当前实时结果。对应文件为 **data/reports/20261123-221124-5985a2.html**。

## 逐分钟讲稿

### 00:00–00:35｜问题与定位

**操作：** 展示首页标题和设备与模型状态条。

**讲稿：**

“各位老师好，我们的项目叫‘应急先行’，面向断网或网络不稳定的现场巡查。普通的图片问答需要人先发现情况、再拍照上传；我们的重点是让系统持续抽取现场画面，先发现人员和烟火线索，再保存事件帧供人复核。系统和模型部署在板端，下面我用本地素材演示这条链路。先说明，目前没有接入摄像头，状态栏也会如实显示各模型当前运行的后端。”

### 00:35–01:35｜持续巡查

**操作：** 打开“持续监测”，选照片演示 01，设为每 2 秒，关闭循环，点击开始。等状态显示运行后，画面会依次切到空场、人员和烟火；烟火事件出现后立即点击“停止”，再指向最新检测帧、事件提醒和事件列表。一般展示前 20–30 秒的素材即可，不必等它播完整段。

**讲稿：**

“这里选择的是项目本地保存的演示视频。它由空场、人员、烟雾和明火的静态图片拼接，主要验证抽帧、检测、事件合并和记录流程，并不等于摄像头的连续实景效果。系统每隔两秒取一帧，运行人员和烟火检测；同一类别连续出现会合并为事件，并保留时间位置和图片。若出现漏检或误报，页面也不会把结果说成现场真相，仍需人工核查。”

### 01:35–02:35｜提交复合问题

**操作：** 打开“巡查工作台”，上传 **ESE_fire_10.jpg**，输入准备好的问题，点击“开始本地分析”。任务运行时展示右侧真实进度。

**讲稿：**

“接下来从自动巡查转到一张具体现场图片。我没有只问‘有没有火’，而是同时问有没有烟雾、明火，以及应该如何避险。Agent 收到问题后会先按需要选择工具。它可以调用烟火检测、人员检测或知识检索；调用步骤会在右侧记录。正在运行的是本机 CPU 模型，所以首次推理和 Qwen 规划需要等待一段时间。这里展示的是实际任务进度，不是预先录好的回答。”

**讲述原则：** 等待期间只介绍已在页面出现的状态和本地执行路径。若模型本轮选择和预期不同，照着实际轨迹讲，不要提前背诵成固定顺序。

### 02:35–03:40｜结果、Agent 决策与证据

**操作：** 任务完成后指出图上的检测框和置信度，展开 Agent 决策与工具执行，再查看风险依据。

**讲稿：**

“结果不是只给一句文本。图上可以看到模型标出的烟雾和明火候选框，下面有检测置信度和工具来源；Agent 区域记录了模型实际选择的动作和工具执行结果。应急建议由检测证据、本地知识和规则共同约束。请注意，置信度不是火灾发生概率，页面里的预警分是实验规则的辅助分级，也不能代替消防判断。图片没有检出目标同样不能证明现场安全。”

### 03:40–04:25｜本地记录与可复核性

**操作：** 展开检测详情，打开 HTML 证据报告，指向样例图片、检测输出、模型来源和记录时间。

**讲稿：**

“这次分析可以保存为巡查记录，并打开 HTML 报告复核输入图片、检测结果、工具执行和回答。项目还保留原始 JSON，便于复现实验或检查异常。展示这些记录的目的，是让结论能够追溯，而不是把一次演示包装成全面的准确率验证。”

### 04:25–05:00｜边界与下一步

**操作：** 回到设备状态条或持续监测状态，结束演示。

**讲稿：**

“目前的边界也很明确：还没有摄像头接入，演示视频是静态图片拼接；告警目前是网页事件和浏览器提示音，没有板载蜂鸣器或远程通知；当前视觉模型运行在 CPU。YOLO 的 NPU 候选还没有通过人员检测验收，火情模型也需要更充分的独立测试。下一步是接入真实摄像头或 RTSP，补齐标注测试，再验证 NPU 精度、报警延迟和长时间稳定性。我们的目标不是让模型替人决定，而是更早提供线索，并留下可以核查的证据。谢谢。”

## 现场应急预案

- **视频没有马上出现事件：** 确认选中“照片演示 01 · 基础轮巡”，关闭循环；运行状态出现后给它约 20–30 秒进入烟火素材段。若仍未检出，不延长等待，说明本轮没有检出并转入单图分析，不把素材标签说成模型结果。
- **Agent 超过两分钟仍未完成：** 点击停止，打开历史记录中同一张 **ESE_fire_10.jpg** 的 HTML 报告；明确标注为“此前运行记录”，继续讲实际检测框和 Agent 轨迹。
- **检测结果与讲稿预想不同：** 展示实际结果，说明单个候选和单次演示不能证明准确率。不要切换到另一张图后把它说成同一次请求。
- **页面提示状态异常：** 使用已保存的 **data/reports/20261123-221124-5985a2.html** 和图片 **samples/fire-smoke/ESE_fire_10.jpg** 讲解证据留存流程，同时明确这是历史记录。

## 排练检查

正式展示前至少完整计时一遍。确认屏幕分辨率、浏览器缩放、演示视频来源提示和状态栏可读；准备好烟火图片文件选择路径；确认网页提示音不会被误称为蜂鸣器；提前打开备用报告，但不要把历史报告显示成实时结果。结束时把下一步归纳成“真实视频、独立验证、NPU 验收、硬件告警”四项。
