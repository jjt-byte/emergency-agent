# 断网应急巡查原型

这是板端的离线巡查原型。它包含本地规则、SQLite 知识检索、本地 GGUF 问答，以及 DAMO-YOLO 人体和烟火检测适配器；保留 CIX SSD 人员检测作为可回退配置。普通问题由 Qwen 直接回答；人数由检测框统计，火情风险由规则给出，避免模型改写证据。报告保存在 `data/reports/`，图片证据保存在 `data/evidence/`，本地知识索引是 `data/knowledge.sqlite3`。

## 本地视频持续监测（2026-11-06）

没有摄像头时，可在网页顶部的“持续监测 · 本地视频验证”中选择视频，点击“开始持续监测”。
默认每 2 秒检测一次，循环回放，启用人员检测与人员出现提醒。无需上传单张照片或输入问题，
后台直接调用人员、烟火检测模型，不调用 Qwen，不等待生成回答。

内置五段“照片演示”视频，由已有本地照片拼接，包含烟雾、明火、人员与空场的不同切换顺序，
时长 60 秒至 2 分钟，可直接在视频选择框中使用。每段画面均标有当前照片场景与切换时刻；
它们只用于体验抽帧、事件合并、提醒与证据保存，不是真实连续拍摄，也不代表模型准确率或现场预警效果。
详细时长、时间表和使用方法见 [照片演示视频使用说明](照片演示视频使用说明.md)。
也可点击“导入本地视频”，导入不超过 200 MB 的 MP4、MOV、MKV、WebM 或 AVI。
视频保存在板卡 `data/monitor/videos/`，不上传公网。

后台按视频播放时间提取最新帧，推理超出设定间隔时跳过已经过去的画面，不积压旧帧；
网页展示的是最新完成检测的图片及检测框，并非实时视频直播。模型分别在独立进程常驻，
同时运行人员和烟火检测，不会为每帧重新加载模型。烟火使用 CPU DAMO-YOLO；人员可使用 CPU DAMO-YOLO，或在 NPU 实测通过后使用 CIX YOLOv8s。每个模型使用其配置的独立 Python 环境。

首次检出人员、烟雾、明火即创建提醒；同一类别连续两次检出会标为“连续检出”，
明火提醒升级为红色。同一类别持续出现时合并成一个事件，连续三次未检出后结束该事件；
这不表示现场安全。“连续检出”也不等于人工确认发生火灾。视频循环边界会重新累计，
不会将两个回放周期的检出拼成连续命中。关闭“人员出现时提醒”可只查看人数。

点击“启用页面提示音”后，首次检出与升级时发声；页面初次打开不重放历史事件的声音。
声音依赖浏览器保持打开和允许音频，后台页面可能受到浏览器节流；目前没有板端蜂鸣器、
后台扬声器或远程通知。关闭网页后检测与证据保存继续运行，停止网页服务会停止检测。
重新启动网页服务后需重新点击开始；当前不包含开机自动监测，也未接入摄像头或 RTSP。

每次监测的数据保存在 `data/monitor/sessions/<编号>/`，包含状态、配置、运行日志，
以及 `events/` 中的事件 JSON 与截图。每次监测保留最近 200 条事件，普通画面只保留最近 3 帧；
网页显示最近一次监测的事件，之前监测的目录仍保存在板卡上。模型失败、取帧失败与进程退出
显示故障，不记为零个目标；停止后的画面明确为最后完成检测的帧。

更新后，在原终端 Ctrl+C 停止服务，重新执行 `./start-web.sh`，浏览器 Ctrl+F5 刷新。
如需重新生成五段照片演示视频：

```bash
cd /home/orangepi/emergency-agent
python3 tools/make_monitor_demo.py --suite
```

这会覆盖同一组演示文件，不影响其他导入视频。原 32 秒单段演示可通过 `python3 tools/make_monitor_demo.py` 生成。

本机 32 秒演示实测：每 2 秒检测一次，共处理 16 帧，出现人员、烟雾和明火提醒，
稳定阶段每轮取帧与两个模型检测合计约 0.8–1 秒。该时间属于此演示与当前板卡环境，
摄像头部署前仍需用实际场景的视频检查漏检、误报、报警延迟和长时间运行情况。
现有烟火模型已有漏检案例，持续抽帧不会自动解决模型对某些烟火无法识别的问题。

## 本地 Agent 模式（2026-10-31）

网页默认勾选“启用Agent（本地Qwen）”。Qwen2.5-3B通过受约束的JSON指令选择人员检测、烟火检测、本地知识检索和预警评估，工具返回后可继续选择下一步，最多三轮工具规划，必要时再调用一次最终回答。普通问题可以直接回答；现场条件不足时可以追问一个具体问题。

网页会显示实际执行步骤及失败、跳过、沿用结果状态；发生紧急预警时先展示避险提示，最终回答随后生成。人数、预警等级、失败与未检出的区别由工具证据校验，不能被生成文本随意改写。模型输出不合法、超时或违背证据时，使用明确标注的工具结果兜底，不把规则补齐步骤冒充模型自主调用。原始决策和工具来源保存在JSON报告中，网页显示简短执行摘要。

同一对话可沿用上一张图片，匹配图片SHA256、模型配置与文件指纹后复用成功的检测结果。失败结果不会复用。上传新图不沿用旧图证据；“移除图片”清除场景图片，“新对话”清除当前会话关联。继续历史记录会在该记录处建立分支。对话只存放于本机 `data/conversations/`，历史消息来自服务端保存的报告，客户端不能指定任意图片路径或伪造工具结果。现场确认勾选不会由模型自动设置。

语言模型和检测均在CPU上运行，不使用公网API。多轮模型调用比原规则模式耗时更多，网页持续显示步骤；每个任务使用临时提示缓存以减少重复前缀计算，任务结束自动清理。当前不提供逐字流式输出。取消“启用Agent”可使用原检测与规则模式。

CLI可显式启用：

```bash
./start.sh run --agent --llm --detect --task "这里有几个人，有火吗，应该怎么办？" --image /path/to/photo.jpg
```

也可以直接调用Python：

```bash
/home/orangepi/modelscope-venv/bin/python agent.py run --agent --llm --detect --task "这里有几个人，有火吗，应该怎么办？" --image /path/to/photo.jpg
```

修改后须重启网页服务，并按Ctrl+F5加载新页面。Agent工具编排不会自动改善原检测模型的漏检，也不增加通用图像问答、实时视频或NPU加速能力。

## 运行

### 桌面软件窗口

板卡有图形桌面时，可以把本地巡查做成独立应用窗口，不需要手动打开浏览器。应用会自动启动本机回环服务，内置持续监测、现场分析、巡查记录、批量测试和知识库工作页，并保留模型、事件、报告和证据的原有目录。

```bash
cd /home/orangepi/emergency-agent
python3 tools/install_desktop.py
```

安装后在桌面双击“应急先行”即可启动，也可以运行 `bash start-desktop.sh`。桌面版说明见 [桌面版使用说明](桌面版使用说明.md)。SSH 或没有图形会话的终端不能显示窗口；这种情况继续使用下面的本地网页启动方式。

### 本地网页

在板卡本机终端运行：

```bash
cd /home/orangepi/emergency-agent
./start-web.sh
```

保留该终端，在板卡浏览器打开 **http://127.0.0.1:8080**。
页面支持自由输入问题、不传图片的本地 Qwen 问答，以及上传 JPG/PNG 检查人员、预案检索、人工复核、历史与报告下载。
页面资源全部在 `web/` 中，使用 Python 标准库提供本机 HTTP 服务，无 CDN、无云端 API。
本地 HTTP 不依赖 Wi-Fi 或公网。按 Ctrl+C 停止；端口被占用时运行 `./start-web.sh --port 8081`。
默认只监听回环地址。需要让同一 Wi-Fi 下的手机或电脑访问时，在原终端按 Ctrl+C，重新运行：

```bash
./start-web.sh --host 0.0.0.0 --port 8080
```

另开一个板卡终端运行 `hostname -I`，找到板卡连接 Wi-Fi 的 IPv4 地址。
例如地址为 `192.168.1.25`，就在其他设备浏览器打开 `http://192.168.1.25:8080`。
页面上传与问答仍在板卡执行；其他设备不用安装模型。局域网连接需要保持，公网可以断开。
使用板卡实际 IP 访问；`127.0.0.1` 在其他设备上指向其他设备自身。
若无法连接，检查是否连接访客 Wi-Fi、路由器是否开启设备隔离，以及板卡防火墙是否放行 TCP 8080。

模型推理在独立进程执行，网页轮询任务状态；刷新页面可继续等待上次任务。
若服务停止中断任务，下次启动会将该任务标记为失败，需重新提交。
复核记录会同步写入 JSON、Markdown 和 HTML，保留复核历史；它不改变原始检测与规则风险等级。
图像以检测框叠加显示，人数需要现场复核。摄像头实时画面和语音输入尚未接入。

输入框没有固定问题。普通问题的回答直接显示在“任务回答”中，支持多行；不再为所有问题统计人数。
图片可选，通过“移除图片”切换为纯文字提问，每次独立处理当前问题。
例如“用三点说明应急包应准备什么”走本地问答；“这张图里有几个人”走人员检测统计；
“检查现场火情风险”说明规则依据及未覆盖能力；“这些人穿什么衣服”说明尚未接入该视觉能力。
只在与问题相关时显示人数和风险栏目。

询问人数时，程序统计模型输出的 person 框，页面“任务回答”直接展示估计数量，
在展开的检测详情中列出置信度不低于 70% 的框数、较低置信度框数及编号。70% 只用于提示复核，
不会把已检测出的较低置信度目标从总估计中删去。该数量仅针对单张图片，可能存在重叠、误检或漏检。
检测失败、未启用检测时显示“无法统计”，不显示 0 人；成功运行且无人员框时显示“未检出”，不认定现场无人。
Qwen 已升级为 Qwen2.5-3B-Instruct，使用 Q4_K_M GGUF（约 1.8 GiB）在 CPU 上推理；它不能直接看图片。
模型位于 `/home/orangepi/models/qwen2.5-3b/qwen2.5-3b-instruct-q4_k_m.gguf`，
由用户下载的原始权重在本地转换、量化，未使用在线推理服务。原 0.5B 文件保留以便回退。
8 个大核、8 线程实测：256 token 输入处理约 27 token/s，128 token 生成约 16 token/s（各重复两次）。
这是短上下文独立测速；网页还包含知识检索、输入处理与完整答案生成，当前不会逐字显示。
配置为 4096 token 上下文、最多生成 384 token；新任务子进程会读取新的 `config.json`，已完成的历史报告保留原模型信息。
升级记录和旧配置备份位置见 `data/llm_upgrade_qwen3b.json`；普通问答与复杂指令的回答仍需核查。
人员图片由专用 DAMO-YOLO 人体检测模型处理；人数主答案不依赖语言模型生成是否成功。人员位置类问题可把框坐标交给 Qwen 解释，仍需人工核查。
人数估计与火情风险分别展示；预警等级与人工复核状态分别显示，预警不会覆盖人员数量。

### CIX YOLOv8s NPU 候选与实测切换

各模型能否迁移、SDK 编译环境和切换步骤见 [CIX 迁移说明](CIX迁移说明.md)。

已准备 `models/person/cix-yolov8s/yolov8s.cix` 和来源 SHA256；来自
`cix/ai_model_hub_yolo_series`，仅取 COCO 的 person 类别，不能检测烟火。
网页、Agent、报告来源和对话缓存均支持 `person_detection.backend=cix_yolov8s`。
默认配置在 NPU 实测通过前继续使用 DAMO CPU。

在板卡本机终端执行：

```bash
cd /home/orangepi/emergency-agent
./test-person-npu.sh --activate
```

此脚本使用现有 NOE 环境和 ffmpeg，无需联网或安装 OpenCV；分别加载两个模型，
每图预热一次再测试三次。对比六张图片的人工参考人数与检测框，保存
`data/person_npu_comparison.json` 和可直接打开的 `data/person_npu_comparison.html`。
耗时为模型已加载后的预处理、推理和后处理总时间，模型加载时间另记。
样例人数依次为 6、3、5、4、5、0；没有参考框，不能据此计算召回率或认定没有漏检。
YOLO 六张样例人数全部正确且多次人数稳定，才写入 NPU 验证标记；加上 `--activate`
才会备份配置并切换，原 DAMO 配置保存在 `person_detection_cpu_fallback`。
推理失败或人数不符时不会自动切换，可查看对比图后再调整。

预处理依据 CIX 的 input0.bin（BGR、640×640 拉伸）和校准数据（0..1）重建；
使用 ffmpeg bilinear 替代缺失的 OpenCV 工具。原始样例像素平均绝对差约 1.49/255，
仍需用实际 NPU 检出结果验证，未直接宣称与官方预处理逐像素相同。

切换成功后，在原网页服务终端 Ctrl+C，然后重新运行：

```bash
./start-web.sh --host 0.0.0.0 --port 8080
```

浏览器 Ctrl+F5 刷新，人员检测状态应显示 CIX YOLOv8s · NPU。烟火与 Qwen 的推理设备独立配置。
若执行环境无法访问 `/dev/aipu`，脚本会明确报阻塞并保留当前配置，不能把软件测试当作 NPU 实测。

单次命令：

```bash

python3 agent.py run \
  --task '检查前方区域并报告风险' \
```

`--detect`（兼容旧参数 `--npu-detect`）按提问选择当前配置的人员或烟火检测工具；现均为 CPU DAMO-YOLO。人体模型没有烟火类别，烟火证据来自另一专用模型。原图、工具状态、检测框、置信度和模型版本会记入报告。

```bash

```

知识检索目前是轻量关键词匹配，会在报告中记录本地文件路径与行号。导入前需确认文档来源和版本，不能将演示文字当作正式处置依据。

## 外部视觉工具接口

外部视觉程序可输出如下 JSON 数组，再传给 `--detections /path/to/detections.json`：

```json
[
  {"label": "smoke", "confidence": 0.82},
  {"label": "person", "confidence": 0.91}
]
```

允许的类别：`fire`、`smoke`、`person`、`blocked_exit`。框坐标可选，格式为像素坐标 `[x1, y1, x2, y2]`。外部 JSON 不能验证结果真伪，报告会标记为 `external_json_unverified`。视觉工具失败时传 `--tool-error`，图片预警分为未知，风险提示为“无法评估：检测未完成”。
